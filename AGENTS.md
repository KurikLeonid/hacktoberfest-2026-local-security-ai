# Инструкции для агентов

Этот файл действует для всего репозитория. Цель проекта — локальная DLP-проверка запросов к AI-чатам. За подробностями запуска и устройства обращайтесь к [README.md](README.md).

## Устройство проекта

1. `backend/proxy/adapters.py` извлекает текст из запросов к поддерживаемым чатам. `backend/proxy/guard.py` выбирает запросы для проверки и применяет итоговое решение.
2. `backend/core/classifier.py` вызывает локальную Gemma 4 через Ollama: находит фрагменты, применяет разрешения домена и проверяет оставшиеся находки на примерах из датасета. `backend/core/policies.py` загружает правила из `policies.yaml`.
3. `backend/core/store.py` хранит события и датасет в SQLite. `backend/api/app.py` отдаёт API и события админке из `frontend/src/`.

## Обязательные инварианты

- DLP-анализ и вызовы Gemma по умолчанию остаются локальными (`DLP_LLM_PROVIDER=ollama`). Единственное разрешённое исключение — явный опциональный режим Gemma 4 через Gemini API (`DLP_LLM_PROVIDER=gemini`, `GEMINI_MODEL=gemma-4-*`), который пользователь включает сам; он должен оставаться выключенным по умолчанию и помеченным в админке. Не заменяйте классификацию закрытыми моделями и не отправляйте события или датасет во внешние диагностические сервисы.
- Ошибка Ollama, невалидный ответ и таймаут должны приводить к `BLOCK` (fail-closed). Не превращайте ошибку классификатора в `ALLOW`.
- Категории `credentials` и `special_pii` запрещены для всех доменов, независимо от whitelist. При изменении правил проверяйте `never_allowed` в `policies.yaml`.
- Не добавляйте исходные запросы и ответы модели в логи, сообщения об ошибках или диагностические выводы. Для диагностики используйте этап, код ошибки, `done_reason`, длину ответа и время; штатное хранение событий в SQLite остаётся отдельным механизмом продукта.
- Не коммитьте `backend/.env`, ключи, локальные базы и логи из `data/`. Они исключены через `.gitignore`.

## Источники истины

- Текущие пороги, категории, домены, модель и таймауты: `policies.yaml`.
- Архитектура, установка и запуск: `README.md`.
- Последний сохранённый результат eval: `docs/EVAL.md`; подробные результаты: `backend/eval/results/`.
- `docs/PROGRESS.md` — хронология решений и прошлых запусков. Её старые значения не заменяют текущую конфигурацию.

## Проверки

Выбирайте проверки по изменённой области. Команды ниже запускаются из каталога, указанного перед блоком.

Backend, из `backend/`:

```bash
uv run python -m unittest discover -s tests -v
```

Frontend, из `frontend/`:

```bash
npm run build
npm run lint
```

Если менялись классификатор, промпты, политики или модель, сначала запускайте затронутые кейсы, затем полный eval на локальной Gemma. Из `backend/`:

```bash
uv run python -m eval.run --provider ollama --model gemma4:e4b --only sp-health-weight,sp-sick-csv
uv run python -m eval.run --provider ollama --model gemma4:e4b
```

`--only` принимает ID кейсов или группы через запятую. Eval создаёт JSON в `backend/eval/results/` и перезаписывает `docs/EVAL.md`; просмотрите оба результата и отдельно сообщите число ошибок модели, утечек и ложных блоков. Для пересборки отчёта без вызова модели используйте `uv run python -m eval.run --report-only` из `backend/`.

## Локальный запуск и системный прокси

Для разработки запускайте из корня `scripts/run.sh --no-system-proxy`: он поднимет локальные сервисы, не меняя сетевые настройки macOS. Обычный `scripts/run.sh` включает системный прокси. После такого запуска проверьте, что он выключился при остановке; если нет, выполните `scripts/dlp-off.sh`.
